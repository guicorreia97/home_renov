# Persistence guide

v1 stores data as **JSON files on disk**. MongoDB comes later. The whole point of
this guide is that the migration must be a change to one folder, not a rewrite.

## The rule

**No code outside `app/src/repositories/` may open a file, parse JSON, or call a
database driver.** Services depend on a repository *interface*, never on how the
bytes are stored. If `json` is imported in a service, that is a defect.

## Shape the data like documents, not tables

Model records the way MongoDB would hold them, so the swap is mechanical:

- Every record has a stable string `id` (a UUID4 as `str`, generated by the
  repository, never by the caller).
- Embed what is always read together (a room's task list); reference what is
  shared or large (a contractor, by `contractor_id`).
- No joins, no foreign-key constraints, no auto-increment integers.
- Timestamps are UTC ISO-8601 strings.

## Interface

Define one `Protocol` per aggregate in `app/src/repositories/`, typed with domain
models:

```python
class RoomRepository(Protocol):
    def get(self, room_id: str) -> Room | None: ...
    def list(self) -> list[Room]: ...
    def add(self, room: RoomCreate) -> Room: ...
    def update(self, room_id: str, changes: RoomUpdate) -> Room: ...
    def delete(self, room_id: str) -> None: ...
```

Then `JsonRoomRepository` implements it now, and `MongoRoomRepository` later.
Services are typed against the Protocol and receive an instance via FastAPI's
`Depends`, so tests can inject an in-memory fake.

## The JSON implementation

- One file per collection: `data/<env>/rooms.json`, holding a JSON array.
- The data directory comes from settings, never a hardcoded path. `data/` is
  gitignored — it is local state, and it is **never** committed.
- **Write atomically**: serialize to a temp file in the same directory, then
  `os.replace()`. A partial write on interrupt otherwise corrupts the file.
- Read-modify-write the whole file per operation. It is O(n) and that is fine at
  v1 scale; do not build an index or a cache to avoid it.
- Guard writes with a module-level lock. Uvicorn is single-process by default,
  but concurrent requests still interleave around `await`.
- A missing file means an empty collection, not an error. Create it on first write.

## Migrating to MongoDB

When it's time: add `MongoRoomRepository` implementing the same Protocol, switch
the `Depends` provider, write a one-off script that reads each JSON file and
inserts its documents. Services and endpoints must not change — **if they do, the
interface was leaking, and that is the bug to fix first.**

Changing the on-disk format requires human review.
